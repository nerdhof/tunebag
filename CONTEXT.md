# Tunebag domain context

Canonical vocabulary for the codebase. Align code and docs with these terms.

## Glossary

- **Release** — one listening item in the Catalog. A Release is either a Mix or an Album. Budgets, Played, Rating, Reject, Skip, tags, Playhead, and Last heard attach to the Release as a whole.
  _Avoid_: Mix (as the umbrella), tune, track (as the catalog item), listening item
- **Mix** — a Release whose audio is a single file (typically a DJ set or one-shot upload). Duration and size are that file’s.
  _Avoid_: using Mix for multi-track albums
- **Album** — a Release whose audio is an ordered list of tracks. Duration and size are the sums of its tracks. Played is past 75% of the whole Album timeline (not per track). Ordered track metadata (stable track ids, titles, durations, source permalinks) is Catalog data on the Release; track File bytes are not.
  _Avoid_: treating Album tracks as separate Releases (v1)
- **Artist** — a source-platform creator whose uploads are ingested into the Catalog as Releases (Mix or Album). Listing shape is platform-defined (e.g. SoundCloud/hearthis → Mix uploads; Bandcamp/YouTube → Album discography tabs), not a single “own uploads” feed across platforms. YouTube Music URLs are the same platform as YouTube, not a separate Catalog platform.
- **Catalog** — the projected, fully replicated metadata on every paired device (artists, releases, tags, ratings, rejects, play history, intents, sequences, assignments). Derived only from the Event log.
- **Catalog projection** — pure Event → Catalog fold (`apply` / replay): merge bookkeeping, sticky Played/Skipped/Artist delete, and LWW/hybrid Playhead rules. `apply` may return `LocalEffects` (File deletes, intent-folder cleanup); CatalogJournal runs them only on live apply via `on_applied`, never on `replay`. Catalog maintenance is not invoked from `on_applied`. Unknown-author buffering is CatalogJournal policy, not projection state.
- **Tag** — free-text label; suggestions prefer existing tags. Intent membership uses AND of required tags. Empty intent tags mean untagged-only only when the artist filter is also empty; with artists set and tags empty, tagged and untagged releases of those artists are eligible.
- **Rating** — score 1–5 (UI may show ★). Separate from reject. Unrated releases may still match a tagged intent.
- **Reject** — “never assign again” until Un-reject. The UI confirms with a second click, then the Device appends a Reject Event immediately (no undo buffer). File bytes are deleted on every device when the Reject ages past the Soft Rejected window (5 minutes from Reject Event author time). Applies to the whole Release (not individual Album tracks) in v1.
- **Un-reject** — clears Reject on a Release so it may re-enter sequences again. Does not by itself restore File bytes; Cache fill / peer / origin fetch run as usual when the Release is assigned.
- **Soft Rejected** — UI visibility: a Rejected Release whose Reject Event author time is younger than 5 minutes. Soft Rejected rows stay in the default Catalog browse and Play history lists (muted). Not a separate Catalog state.
  _Avoid_: pending reject, undo window (as the product model)
- **Hard Rejected** — UI visibility: a Rejected Release older than the Soft Rejected window. Shown only when that surface’s Rejected filter is on (default off). Not a separate Catalog state.
- **Rating distribution** — draw chances for 5★ / 4★ / 3★ / 2★ / 1★ / unrated (must sum to 1; default 0.3 / 0.2 / 0.1 / 0.05 / 0.05 / 0.3).
- **Intent** — shared plan: tag filter + optional artist filter (`artist_ids`, OR membership) + platform/source filter (`platforms`, OR membership; default all ingest sources; at least one required) + rating distribution. Devices attach hours and optional expiry.
- **Sequence** — seeded ordered list of releases for one intent. It fills until cumulative duration is at least the largest device budget, and may include the release that crosses that budget.
- **Assignment** — which device hours cover which prefix of the sequence (independent of whether audio is on disk).
- **File** — audio bytes present on a device for a Release (local cache state): one blob for a Mix, or an ordered set of track files for an Album. An Album is not present in Cache until every track file is local.
- **Cover URL** — optional remote artwork URL on a Release (Catalog / `MIX_ADDED`). Cover **image bytes** are device-local (`data_dir/covers/`), not Event-log and not audio Cache / metered fill.
- **Cache** — the set of files a device currently holds for its assignments.
- **Release Cache** — device-local module that owns File completeness, staging, blob/intent-folder paths, and `ensure_complete` (peer then optional origin via injected fetch ports). Urgency ordering, metered caps, and preferred-origin policy stay on the DeviceAgent; Mix vs Album layout is internal.
- **Release layout** — pure helpers for Album timeline → track offset and on-disk Mix/Album filenames (shared by Release Cache and Playback supervision).
- **Playback supervision** — device-local module that owns the AudioPlayer, timeline anchors, Album track advance, auto-continue choice, and Played / Last heard thresholds. Emits structured intents (`ReportPlayhead`, `EmitLastHeard`, `MarkPlayed`, `ContinueTo`); DeviceAgent appends Events and resolves Cache paths. Playing state is not an Event.
- **Catalog maintenance** — device-local follow-up after Catalog mutations (`after_catalog_change`): sequence rebuild, Cache fill, and prune. Rebuild is requested via SequenceProvisioner; fill/prune stay here. Not Events themselves (rebuild commits by appending Sequence/Assignment Events).
- **SequenceProvisioner** — module that decides whether an Intent needs a Sequence rebuild and returns Event drafts (`SEQUENCE_BUILT`, `ASSIGNMENT_CLEARED`, `ASSIGNMENT_SET`). Pure helpers `build_sequence` / `assign_by_budget` stay in `sequence.py`. The caller appends drafts (typically via `CatalogJournal.append_local` under `hold()`). Does not own Cache fill or prune.
  _Avoid_: folding fill/prune into the provisioner; depending on CatalogJournal directly
- **Device** — a Tunebag installation with a stable identity (`device_id` + keypair) that authors Event log entries. Identity is not a network address.
- **Locator** — an ephemeral reachability hint for a Device (HTTP URL, IP:port, USB path, …). Locators change with the network; they are not Identity.
- **Peer** — another Device that has paired with this one and is reachable over LAN or USB, usable as a file source.
  _Avoid_: client (as a domain role)
- **Metered** — network mode that caps origin downloads to current release + one ahead per intent.
- **Fill now** — one-shot override that fills one intent to its full device budget on a metered link.
- **Playhead** — last known position on a Release’s timeline across Devices (`position_seconds` from the start of the Release; for an Album, across the concatenated track timeline). Within 2 minutes of author-time delta, higher `position_seconds` wins; beyond 2 minutes, later author time wins.
- **Played** — listened past 75% of the Release’s duration, or explicitly marked played.
- **Skipped** — abandoned via Skip without counting as Played. After a 5‑minute local delay the Device commits a sticky Skipped Event; sequence rebuild then puts the Release at the back of its star bucket (same pool position as Played). Independent of Played: `played` stays false; artist played‑% and other Played stats ignore Skipped. Pending skip is canceled if the Release is played again, marked Played, or Rejected before the delay ends. File bytes may be deleted once a replacement assigned Release is local (same cleanup as Played). Applies to the whole Release (not individual Album tracks) in v1.
- **Last heard** — Catalog-global timestamp on a Release: the latest time any Device crossed the meaningful-listen threshold for that Release. Threshold is position reaching `min(10 seconds, 2% of duration)`. Emit a Last heard Event only on the rising edge (position crosses the threshold from below); not on every playhead tick. Independent of Played. Merge keeps the latest Last heard (signed author time, then `(device_id, seq, event.id)`).
- **Play history** — UI section over Catalog Releases that have a Last heard, ordered by Last heard (newest first). One row per Release; not a list of play occurrences. No backfill: Last heard only from Events after the feature exists. Soft Rejected rows stay visible (muted); Hard Rejected via a Rejected filter (default off). From this view: Rate, Tag, Reject (confirm-click) or Un-reject, and resume at Playhead. See `docs/UI-ACTIONS.md`.
  _Avoid_: listen log, play session, playback history (as a separate entity)
- **Catalog browse** — full Release list (not Last-heard-ordered). Soft Rejected rows stay visible (muted); Hard Rejected via a Rejected filter (default off), independent of Play history’s filter. From this view: Rate, Tag, Reject (confirm-click) or Un-reject (same annotate kit as Play history, minus resume). Artist overview rows show release count + total duration plus rollup rates over all releases (avg rating among rated, rated %, tagged %, reject %, played %), even when the Rejected filter is off. See `docs/UI-ACTIONS.md`.
- **Event log** — the source of truth for Catalog: a signed append-only stream of catalog changes, replicated between paired Peers. Same events ⇒ same Catalog, independent of apply order (per-type deterministic merge). LWW fields order by signed author time then `(device_id, seq, event.id)`; Playhead uses the hybrid author-time rule above.
  _Avoid_: ledger, blockchain
- **CatalogJournal** — device-local module that owns the Event log spine: signing ports, per-author `seq`, dedupe (`seen_ids`), RLock, unknown-author buffer, `append_local` / `ingest_foreign` / `replay` / `export`, and calling Catalog projection `apply`. Live `append_local` / `ingest_foreign` invoke `on_applied(event, effects)` under the lock for LocalEffects and trust reactions (unpair session cleanup). After a live `DEVICE_PAIRED` apply, the journal flushes that author’s buffered Events (re-entrant `ingest_foreign`) before `on_applied`. `replay` rebuilds Catalog only — it does not call `on_applied` (no File/folder side effects on boot). Multi-step atomic sections use `hold()`. DeviceAgent keeps domain verbs, UI view marks, and auto-sync scheduling outside the journal.
  _Avoid_: EventSpine (design name rejected), treating EventLog alone as the spine

## Boundaries

- Catalog replicates via the Event log. Audio does not, except as needed by assignments. Album track *metadata* replicates; Album track *bytes* follow the same Cache/assignment rules as Mix bytes.
- Wire/API names may still say `mix` / `mix_id` until a dedicated rename pass; the domain term is Release.
- Durable across restart: Device identity, trusted Peer identities (public keys / device ids), last-known Locators as non-authoritative hints, and the Event log. Catalog is rebuilt by replaying the Event log; a disposable on-disk Catalog snapshot may accelerate boot but is never authoritative.
- Local-only (not Event log): File bytes, Cover image bytes, Metered flag, deferred File delete until Soft Rejected ages to Hard Rejected, in-progress Skip delay timer, now-playing / local playback supervision, sequence rebuild + Cache fill after Catalog changes (Catalog maintenance), device private key material (key material is durable locally, not replicated). Soft/Hard Rejected are UI visibility over Catalog Reject, not local-only flags.
- Companion UI action jobs, verb labels, surface×action matrix, and view-notice reactivity live in `docs/UI-ACTIONS.md` (not in this glossary). Reject confirm-click and the 5‑minute soft window: `docs/adr/0007-reject-confirm-and-soft-window.md`.
- Natural end of a Release auto-continues to the next later local assigned Release in the playing Intent (no wrap). Skip still wraps and starts the skip delay. Playing state is not an Event.
- On Play, this Device best-effort asks reachable trusted Peers to yield local playback (pause if they are playing) so only one Device is audible. Unreachable Peers are left alone. Playing state is not an Event.
- Peers meet via LAN discovery and/or a listener-supplied Locator (paste/QR). A Locator never grants trust. Before sync, the process at that Locator must prove possession of the trusted Peer’s private key (challenge–response). Discovery matching a trusted public key may refresh Locator hints after proof; an unknown advertisement is only a pair candidate.
- LAN discovery uses mDNS/DNS-SD. Advertisements carry name, key fingerprint, and enough to form a Locator; the full public key is fetched (e.g. pairing payload) before challenge. Browse on agent start, on network/interface change, and with a slow periodic refresh while no trusted Peer has a live session. Discovery is same-LAN only (multicast domain); other networks use paste Locator or USB — no relay in this pass.
- Trust is established only via an ephemeral pairing session: one-time PIN (optional QR of the same offer), signed join, and dual-device Confirm of a matching SAS (first pair, or re-pair after unpair). Fingerprints label devices; they are not pairing secrets. Re-meeting a still-trusted Peer uses discovery/hint + key proof — no rescan.
- Peers exchange Event log entries when they can reach each other; dedupe by event id. Incremental meet uses per-author seq watermarks (`POST /api/events/pull` with `{ "<device_id>": <max_seq>, ... }`), not a single event id.
- Events whose author Device is not yet known are buffered until that Device is paired into the Catalog, not silently dropped.
- Concurrent Event log merge (same event set, any order): Artist/Release add and Device paired are idempotent upserts; Artist delete, Played, and Skipped are sticky; Reject / Un-reject, Rating, Mix tags (`MIX_TAG_ADDED` / `MIX_TAG_REMOVED` last-write-wins per `(mix_id, tag)`; legacy `MIX_TAGGED` replays expand onto those per-tag keys), Intent metadata (name/tags/artist_ids/platforms/distribution/seed) upsert/delete, Sequence, Assignment, and Last heard use last-by signed author time then `(device_id, seq, event.id)` (Intent delete beats an older upsert under that order; Un-reject beats an older Reject under that order and vice versa; Last heard is latest timestamp under that order); Intent `device_hours` merge per `(intent_id, device_id)` under that same order (omission does not clear — removals carry explicit `cleared_device_ids` on the upsert); Playhead uses the hybrid rule above. Per-author `seq` is monotonic so same-Device rebuilds stay causal when `created_at` ties.
- Author time (`created_at`) is part of the signed Event payload.
- Unpair is a replicated `DEVICE_UNPAIRED` event: after it applies, that Device’s future events are not trusted for Catalog. Drop that Peer’s Locator hints, buffered events, and `device_hours` / assignments for it; already-applied Catalog effects from its past events (releases, intents, tags, …) remain.
- A successful key proof at a Locator lasts for the live meet/session until disconnect or failure; rediscovery or a new hint after loss of reachability requires proving again.
- On disk: one SQLite durable bag (`tunebag.sqlite`) holds the append-only Event log, local Device identity, last-known Locator hints, and a disposable Catalog snapshot. Trusted Peer identities (public keys / device ids) live in the Event log via pairing Events, not a trust sidecar. Catalog is not a separate durable authority.
- Our player is the source of play / rating / reject / tag / playhead signals in v1.
- External players may open intent folders; they do not write Tunebag signals in v1. Intent folders place each Mix as one file and each Album as a subfolder of ordered track files.
