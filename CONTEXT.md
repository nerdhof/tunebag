# Tunebag domain context

Canonical vocabulary for the codebase. Align code and docs with these terms.

## Glossary

- **Release** — one listening item in the Catalog. A Release is either a Mix or an Album. Budgets, Played, Rating, Reject, Skip, tags, Playhead, and Last heard attach to the Release as a whole.
  _Avoid_: Mix (as the umbrella), tune, track (as the catalog item), listening item
- **Mix** — a Release whose audio is a single file (typically a DJ set or one-shot upload). Duration and size are that file’s.
  _Avoid_: using Mix for multi-track albums
- **Album** — a Release whose audio is an ordered list of tracks. Duration and size are the sums of its tracks. Played is natural end of the whole Album timeline (not per track). Ordered track metadata (stable track ids, titles, durations, source permalinks) is Catalog data on the Release; track File bytes are not.
  _Avoid_: treating Album tracks as separate Releases (v1)
- **Artist** — a source-platform creator whose uploads are ingested into the Catalog as Releases (Mix or Album). Listing shape is platform-defined (e.g. SoundCloud/hearthis → Mix uploads; Bandcamp/YouTube → Album discography tabs), not a single “own uploads” feed across platforms. YouTube Music URLs are the same platform as YouTube, not a separate Catalog platform. Artist delete is sticky: it removes the Artist and their Releases, strips that id from every Intent’s `artist_ids`, and deletes any Intent that becomes artistless (no remaining artist filter).
- **Catalog** — the projected, fully replicated metadata on every paired device (artists, releases, tags, ratings, rejects, Last heard, intents, sequences, assignments). Derived only from the Event log.
- **Catalog projection** — pure Event → Catalog fold (`apply` / replay): merge bookkeeping, sticky Played/Skipped/Artist delete (including Intent `artist_ids` strip / artistless Intent delete), and LWW/hybrid Playhead rules. `apply` may return `LocalEffects` (File deletes, intent-folder cleanup); CatalogJournal runs them only on live apply via `on_applied`, never on `replay`. Catalog maintenance is not invoked from `on_applied`. Unknown-author buffering is CatalogJournal policy, not projection state.
- **Tag** — free-text label; suggestions prefer existing tags. Intent membership uses OR of required tags (release matches if it has any of them). Empty intent tags mean no tag filter (tagged and untagged). The intent-only sentinel `—` (`UNTAGGED_TAG`) alone means untagged-only. Artist filter is independent.
- **Rating** — score 1–5 (UI may show ★). Separate from reject. Unrated releases may still match a tagged intent.
- **Reject** — “never assign again” until Un-reject. The UI confirms with a second click, then the Device appends a Reject Event immediately (no undo buffer). Catalog maintenance then runs Sequence fillup (same as Played / Skipped: drop this Release from Sequences; keep remaining queued order; append only if device hours need it). File bytes are deleted on every device when the Reject ages past the Soft Rejected window (5 minutes from Reject Event author time). Applies to the whole Release (not individual Album tracks) in v1.
- **Un-reject** — clears Reject on a Release so it may re-enter sequences again. Does not by itself restore File bytes; Cache fill / peer / origin fetch run as usual when the Release is assigned.
- **Soft Rejected** — UI visibility: a Rejected Release whose Reject Event author time is younger than 5 minutes. Soft Rejected rows stay in the default Catalog browse (muted) and remain visible in the Playlog window while Soft (✕ + size). Not a separate Catalog state.
  _Avoid_: pending reject, undo window (as the product model)
- **Hard Rejected** — UI visibility: a Rejected Release older than the Soft Rejected window. Shown only when that surface’s Rejected filter is on (default off). Not a separate Catalog state.
- **Rating distribution** — draw chances for 5★ / 4★ / 3★ / 2★ / 1★ / unrated (must sum to 1; default 0.3 / 0.2 / 0.1 / 0.05 / 0.05 / 0.3).
- **Intent** — shared plan: tag filter (`tags`, OR membership; empty = no tag filter; `["—"]` = untagged-only) + optional artist filter (`artist_ids`, OR membership; create/update reject unknown artists; Artist delete strips deleted ids and removes Intents left with an empty artist filter) + platform/source filter (`platforms`, OR membership; default all ingest sources; at least one required) + rating distribution. Devices attach hours and optional expiry.
- **Sequence** — seeded ordered list of releases for one intent. It fills until cumulative duration is at least the largest device budget, and may include the release that crosses that budget.
- **Sequence fillup** — drop Played, Skipped, and Rejected Releases from the Sequence; keep the relative order of remaining (still-queued) entries; append new draws only until cumulative duration meets the largest device budget; then refresh Assignments. Used after Played, sticky Skipped, and Reject so the upcoming queue does not reshuffle. New draws still place Played/Skipped Releases at the back of their star bucket (Rejected stay ineligible).
  _Avoid_: treating fillup as a full Sequence rebuild; reshuffling upcoming entries on finish, skip, or reject
- **Drop** — remove a Release from one Intent’s Sequence without Played / Skipped / Reject. Device trims that entry from the current Sequence, then runs Sequence fillup (remaining order kept; append if device hours need it). The Release stays eligible for this Intent and may re-enter at another position on the same or a later fillup. Peers see only the resulting `SEQUENCE_BUILT` / assignments (no durable exclusion Event). Not available for the live current Release of that Intent (use Skip). See `docs/adr/0010-sequence-drop.md`.
  _Avoid_: Discard, dequeue, unenqueue (as the product verb); treating Drop as Reject or Skip
- **Queue** — place a matching Release at the **front** or **back** of one Intent’s Sequence without Played / Skipped / Reject or switching playback. If the Release is already in that Sequence, it is moved (removed then inserted). Device then runs Sequence fillup. Peers see only the resulting `SEQUENCE_BUILT` / assignments (no durable Queue Event). Not available for Rejected Releases or the live current Release of that Intent (use Skip). See `docs/adr/0012-sequence-queue.md`.
  _Avoid_: enqueue, pin, bump (as the product verb); treating Queue as Switch to intent / Play now
- **Assignment** — which device hours cover which prefix of the sequence (independent of whether audio is on disk).
- **File** — audio bytes present on a device for a Release (local cache state): one blob for a Mix, or an ordered set of track files for an Album. An Album is not present in Cache until every track file is local.
- **Cover URL** — optional remote artwork URL on a Release (Catalog / `MIX_ADDED`). Cover **image bytes** are device-local (`data_dir/covers/`), not Event-log and not audio Cache / metered fill.
- **Cache** — the set of files a device currently holds for its assignments. Background fill starts on agent start and keeps fetching the soonest-needed **actionable** assigned Release until none remain; Metered-beyond-window and preferred-peer-wait gaps stay pending (idle) until a re-kick (play / current mix, unmetered, peer cache, connect, Catalog maintenance).
- **Release Cache** — device-local module that owns File completeness, staging, blob/intent-folder paths, and `ensure_complete` (peer then optional origin via injected fetch ports). Urgency ordering, metered caps, and preferred-origin policy stay on the DeviceAgent; Mix vs Album layout is internal.
- **Release layout** — pure helpers for Album timeline → track offset and on-disk Mix/Album filenames (shared by Release Cache and Playback supervision).
- **Playback supervision** — device-local module that owns the AudioPlayer, timeline anchors, Album track advance, auto-continue choice, and end-of-Release completion. Emits structured intents (`ReportPlayhead`, `EmitLastHeard`, `MarkPlayed`, `ContinueTo`); DeviceAgent appends Events and resolves Cache paths. Playing state is not an Event.
- **Catalog maintenance** — device-local follow-up after Catalog mutations (`after_catalog_change`): Sequence rebuild or Sequence fillup, Cache fill, and prune. Rebuild/fillup are requested via SequenceProvisioner; fill/prune stay here. Not Events themselves (rebuild/fillup commit by appending Sequence/Assignment Events). Played, sticky Skipped, and Reject use Sequence fillup; Intent upsert, Un-reject, artist delete, and explicit Regenerate sequence use full rebuild. Drop and Queue trim/place then fillup for that Intent inside the agent verb (then Cache fill / prune), not via a CatalogChangeReason.
- **SequenceProvisioner** — module that decides whether an Intent needs a Sequence rebuild or Sequence fillup and returns Event drafts (`SEQUENCE_BUILT`, `ASSIGNMENT_CLEARED`, `ASSIGNMENT_SET`). Fillup drops retired entries, preserves remaining order, and appends only as needed for device budgets; rebuild redraws the whole Sequence. Pure helpers `build_sequence` / `fill_sequence` / `assign_by_budget` stay in `sequence.py`. The caller appends drafts (typically via `CatalogJournal.append_local` under `hold()`). Does not own Cache fill or prune.
  _Avoid_: folding fill/prune into the provisioner; depending on CatalogJournal directly; using full rebuild for Played / Skipped / Reject
- **Device** — a Tunebag installation with a stable identity (`device_id` + Event-signing keypair + Device TLS cert) that authors Event log entries and meets Peers. Identity is not a network address.
- **Device TLS cert** — the TLS certificate/keypair that authenticates this Device on the Peer listener. Distinct from the Event-signing keypair. Fingerprint is bound at pairing (TOFU) and pinned for later meets.
  _Avoid_: treating the Event-signing key as the TLS credential; browser client certificates for the companion UI
- **Locator** — an ephemeral reachability hint for a Device (HTTPS Peer URL, IP:port, USB path, …). Locators change with the network; they are not Identity. Peer Locators address the Peer listener, not the companion UI listener.
- **Peer** — another Device that has paired with this one and is reachable over LAN or USB, usable as a file source.
  _Avoid_: client (as a domain role)
- **Peer meet** — a live mTLS session with a trusted Peer on the Peer listener: mutual cert pin, encrypted Event pull and File transfer, reachability-scoped until disconnect, failure, or unpair. First pairing may TOFU the peer cert into the pairing transcript; after trust, cert mismatch requires re-pair.
  _Avoid_: cleartext HTTP sync/file share; opaque bearer-over-HTTP as the meet; treating Locator reachability alone as meet
- **Peer listener** — the Device’s HTTPS mTLS endpoint Peers use for meet (Event pull, File HEAD/GET, pairing guest hits, fill/sync nudges).
- **UI listener** — the Device’s local cleartext HTTP endpoint for the companion UI (and, long-term, native clients talking to the local agent). Does not serve Peer Event pull or File bytes.
- **Metered** — network mode that caps origin downloads to current release + one ahead per intent.
- **Fill now** — one-shot override that fills one intent to its full device budget on a metered link.
- **Playhead** — last known position on a Release’s timeline across Devices (`position_seconds` from the start of the Release; for an Album, across the concatenated track timeline). Same-Device updates are causal last-write (rewinds like Stop → 0 are accepted). Cross-Device conflicts: within 2 minutes of author-time delta, higher `position_seconds` wins; beyond 2 minutes, later author time wins.
- **Played** — natural end of the Release (Mix file or Album timeline), or companion **Mark played** (completes + advances). No mid-song %. Catalog maintenance then runs Sequence fillup (drop this Release from the Sequence; keep remaining queued order; append only if any device budget is underfilled). For later draws the Release sits at the back of its star bucket.
- **Skipped** — abandoned via Skip without counting as Played. After a 5‑minute local delay the Device commits a sticky Skipped Event; Catalog maintenance then runs Sequence fillup (same as Played). Independent of Played: `played` stays false; artist played‑% and other Played stats ignore Skipped. Pending skip is canceled if the Release is played again, marked Played, or Rejected before the delay ends. Immediate Skip does not change the Sequence. File bytes may be deleted once a replacement assigned Release is local (same cleanup as Played). Applies to the whole Release (not individual Album tracks) in v1.
- **Last heard** — Catalog-global timestamp on a Release: the latest time any Device finished that Release (natural end or Mark played, together with Played). Not emitted mid-song or on Skip/Stop. Merge keeps the latest Last heard (signed author time, then `(device_id, seq, event.id)`).
- **Playlog** — companion UI indexed relative to the current Release (`0`) with past (`−`) and upcoming (`+`), Cache status, and ▶ / ◀ / ⏸ actions. Display window is −20…+50; a trailing `…` row marks when more assignment titles follow. Past is Catalog-global completed (Played) Releases ordered by Last heard (newest first; any Device / Intent; Hard Rejected omitted, Soft Rejected stay). Current and upcoming are the selected Intent’s assignment order. Each entry is one sticky-friendly row: Cover (hover ▶ / ◀ / ⏸) beside a two-line stack (`artist - title`, then Rate / Tag / Reject), with Length and Cache stacked on the right; upcoming `#` hover offers **Drop from sequence**. Device-local **previous-File cushion** keeps the immediate previous Release’s bytes for 5 minutes (same duration as Soft Reject, separate reason) so ◀ can replay it. See `docs/UI-ACTIONS.md`.
  _Avoid_: Play history, listen log, play session (as the product surface name)
- **Catalog browse** — full Release list (not assignment-ordered). Soft Rejected rows stay visible (muted); Hard Rejected via a Rejected filter (default off). From this view: Rate, Tag, Reject (confirm-click) or Un-reject (same annotate kit as Playlog); **Queue** from the cover (hover upper/lower; touch swipe) onto a matching Intent’s Sequence. Artist overview rows show release count + total duration plus rollup rates over all releases (avg rating among rated, rated %, tagged %, reject %, played %), even when the Rejected filter is off. See `docs/UI-ACTIONS.md`.
- **Event log** — the source of truth for Catalog: a signed append-only stream of catalog changes, replicated between paired Peers. Same events ⇒ same Catalog, independent of apply order (per-type deterministic merge). LWW fields order by signed author time then `(device_id, seq, event.id)`; Playhead uses the hybrid author-time rule above.
  _Avoid_: ledger, blockchain
- **CatalogJournal** — device-local module that owns the Event log spine: signing ports, per-author `seq`, dedupe (`seen_ids`), RLock, unknown-author buffer, `append_local` / `ingest_foreign` / `replay` / `export`, and calling Catalog projection `apply`. Live `append_local` / `ingest_foreign` invoke `on_applied(event, effects)` under the lock for LocalEffects and trust reactions (unpair session cleanup). After a live `DEVICE_PAIRED` apply, the journal flushes that author’s buffered Events (re-entrant `ingest_foreign`) before `on_applied`. `replay` rebuilds Catalog only — it does not call `on_applied` (no File/folder side effects on boot). Multi-step atomic sections use `hold()`. DeviceAgent keeps domain verbs, UI view marks, and auto-sync scheduling outside the journal.
  _Avoid_: EventSpine (design name rejected), treating EventLog alone as the spine

## Boundaries

- Catalog replicates via the Event log. Audio does not, except as needed by assignments. Album track *metadata* replicates; Album track *bytes* follow the same Cache/assignment rules as Mix bytes.
- Wire/API names may still say `mix` / `mix_id` until a dedicated rename pass; the domain term is Release.
- Durable across restart: Device identity (including Device TLS cert material), trusted Peer identities (Event-signing public keys / device ids and pinned Peer TLS cert fingerprints), last-known Locators as non-authoritative hints, and the Event log. Catalog is rebuilt by replaying the Event log; a disposable on-disk Catalog snapshot may accelerate boot but is never authoritative.
- Local-only (not Event log): File bytes, Cover image bytes, Metered flag, deferred File delete until Soft Rejected ages to Hard Rejected, Playlog previous-File cushion (5 minutes), in-progress Skip delay timer, now-playing / local playback supervision, Sequence rebuild / Sequence fillup + Cache fill after Catalog changes (Catalog maintenance), device private key material and Device TLS private key (durable locally, not replicated). Soft/Hard Rejected are UI visibility over Catalog Reject, not local-only flags.
- Companion UI action jobs, verb labels, surface×action matrix, and view-notice reactivity live in `docs/UI-ACTIONS.md` (not in this glossary). Reject confirm-click and the 5‑minute soft window: `docs/adr/0007-reject-confirm-and-soft-window.md`. Sequence fillup vs full rebuild on Played / Skipped / Reject: `docs/adr/0009-sequence-fillup-on-played-skipped.md`. Drop from sequence (trim + fillup, no exclusion Event): `docs/adr/0010-sequence-drop.md`. mTLS Peer meet, split listeners, and Cache file share: `docs/adr/0011-mtls-peer-meet-and-cache-file-share.md`. Queue onto sequence (place front/back + fillup, no Queue Event): `docs/adr/0012-sequence-queue.md`.
- Natural end of a Release auto-continues to the next later local assigned Release in the playing Intent (no wrap). Skip still wraps and starts the skip delay. Playing state is not an Event.
- On Play, this Device best-effort asks reachable trusted Peers to yield local playback (pause if they are playing) so only one Device is audible. Unreachable Peers are left alone. Playing state is not an Event.
- Peers meet via LAN discovery and/or a listener-supplied Locator (paste/QR) to the Peer listener. A Locator never grants trust. Peer meet is mTLS with cert pin to the trusted Peer’s Device TLS cert (see `docs/adr/0011-mtls-peer-meet-and-cache-file-share.md`). Discovery matching a trusted public key may refresh Locator hints after a successful meet; an unknown advertisement is only a pair candidate.
- LAN discovery uses mDNS/DNS-SD. Advertisements carry name, key fingerprint, and enough to form a Peer Locator; the full Event-signing public key and TLS cert material needed for pin/TOFU are fetched (e.g. pairing payload) before meet. Browse on agent start, on network/interface change, and with a slow periodic refresh while no trusted Peer has a live Peer meet. Discovery is same-LAN only (multicast domain); other networks use paste Locator or USB — no relay in this pass.
- Trust is established only via an ephemeral pairing session: one-time PIN (optional QR of the same offer), signed join, and dual-device Confirm of a matching SAS (first pair, or re-pair after unpair). Pairing may TOFU the peer Device TLS cert into that transcript; Event-signing fingerprints label devices and are not pairing secrets. Re-meeting a still-trusted Peer uses discovery/hint + mTLS pin match — no rescan; cert change requires re-pair.
- Peers exchange Event log entries over Peer meet when they can reach each other; dedupe by event id. Incremental meet uses per-author seq watermarks (`POST /api/events/pull` with `{ "<device_id>": <max_seq>, ... }`), not a single event id. Unauthenticated cleartext Event pull is not accepted.
- Assigned File bytes are copied pull-style over Peer meet before origin when a live Peer can supply a complete Release (Mix blob or all Album tracks). Presence uses a cheap HEAD/has probe; Album remains all-or-nothing. Preferred-origin wait, supply checks, and fill nudges treat live HTTP Peers like in-process Peers. Peer/USB copies stay outside Metered origin caps. USB file copy remains a later transport.
- Events whose author Device is not yet known are buffered until that Device is paired into the Catalog, not silently dropped.
- Concurrent Event log merge (same event set, any order): Artist/Release add and Device paired are idempotent upserts; Artist delete, Played, and Skipped are sticky (Artist delete also strips that id from Intent `artist_ids` and deletes Intents that become artistless, advancing the Intent merge beat so an older upsert cannot resurrect them; Intent upsert drops `artist_ids` already in `deleted_artists`); Reject / Un-reject, Rating, Mix tags (`MIX_TAG_ADDED` / `MIX_TAG_REMOVED` last-write-wins per `(mix_id, tag)`; legacy `MIX_TAGGED` replays expand onto those per-tag keys), Intent metadata (name/tags/artist_ids/platforms/distribution/seed) upsert/delete, Sequence, Assignment, and Last heard use last-by signed author time then `(device_id, seq, event.id)` (Intent delete beats an older upsert under that order; Un-reject beats an older Reject under that order and vice versa; Last heard is latest timestamp under that order); Intent `device_hours` merge per `(intent_id, device_id)` under that same order (omission does not clear — removals carry explicit `cleared_device_ids` on the upsert); Playhead is same-Device causal LWW, cross-Device hybrid as above. Per-author `seq` is monotonic so same-Device rebuilds stay causal when `created_at` ties.
- Author time (`created_at`) is part of the signed Event payload.
- Unpair is a replicated `DEVICE_UNPAIRED` event: after it applies, that Device’s future events are not trusted for Catalog. Drop that Peer’s Locator hints, buffered events, and `device_hours` / assignments for it; already-applied Catalog effects from its past events (releases, intents, tags, …) remain.
- A successful Peer meet lasts until disconnect, authenticated-call failure, or unpair; rediscovery or a new hint after loss of reachability requires meeting again (mTLS pin).
- On disk: one SQLite durable bag (`tunebag.sqlite`) holds the append-only Event log, local Device identity (Event-signing keys + Device TLS cert material), last-known Locator hints, and a disposable Catalog snapshot. Trusted Peer identities (Event-signing public keys / device ids and pinned TLS cert fingerprints) live in the Event log via pairing Events, not a trust sidecar. Catalog is not a separate durable authority.
- Companion UI (interim) uses the UI listener; native clients are expected to replace it long-term and still talk to the local agent, not to Peers’ Peer listeners.
- Our player is the source of play / rating / reject / tag / playhead signals in v1.
- External players may open intent folders; they do not write Tunebag signals in v1. Intent folders place each Mix as one file and each Album as a subfolder of ordered track files.
